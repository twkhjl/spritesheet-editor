# Spritesheet 播放器改造設計

## 目標

將現有的單圖走路動畫生成工具改造成純前端 spritesheet 播放器。使用者選取本機圖片後即可預覽逐格動畫，不再呼叫 NVIDIA API、不執行本機生成，也不把圖片上傳至伺服器。

## 使用流程

1. 使用者選取或拖放一張 PNG、JPEG 或 WebP spritesheet。
2. 頁面讀取圖片尺寸，顯示完整圖表預覽。
3. 使用者設定欄數、列數、總幀數與 FPS。
4. 播放器依左到右、上到下的順序播放有效格子。
5. 使用者可播放、暫停、切換上一幀或下一幀、開關循環及調整預覽縮放。

預設值為 5 欄、5 列、25 幀及 12 FPS。

## 介面設計

左側保留素材與設定區：

- 圖片拖放／選取。
- 欄數、列數、總幀數及 FPS 數字輸入。
- 循環播放開關。
- 圖片名稱、像素尺寸及單格尺寸摘要。

右側為播放工作區：

- 單格動畫預覽。
- 完整 spritesheet 與格線預覽。
- 播放／暫停、上一幀、下一幀控制。
- 當前幀編號與總幀數。
- 預覽縮放控制。

介面沿用現有深色像素工作台的視覺方向，但所有生成、進度、供應商與下載文案改為播放器語意。

## 資料與動畫模型

圖片使用 `URL.createObjectURL` 載入瀏覽器，不建立上傳請求。播放器維護以下狀態：

- 圖片 URL、原始寬高。
- 欄數與列數。
- 總幀數。
- FPS。
- 當前幀、播放狀態、循環設定及縮放比例。

每格來源尺寸為圖片寬度除以欄數、圖片高度除以列數。動畫預覽使用 CSS `background-image`、`background-size` 與 `background-position` 顯示單一格子，不重新編碼圖片。

## 驗證與錯誤處理

- 只接受 PNG、JPEG 與 WebP。
- 欄數、列數及 FPS 必須是正整數。
- 總幀數必須介於 1 與「欄數 × 列數」之間。
- 圖片寬高不必整除格數；介面會顯示小數單格尺寸並提示可能存在格線誤差。
- 更換圖片時停止播放、回到第 1 幀，並釋放舊的 object URL。
- 非圖片或瀏覽器無法解碼的檔案顯示安全化錯誤訊息。
- 關閉循環時，播放到最後一幀即停止。

## 架構調整

- Express 僅提供 `public` 靜態檔案與首頁 fallback。
- 刪除生成任務 API、任務佇列、NVIDIA provider、影片抽幀、圖片生成與本機備援程式。
- 移除不再使用的 `multer`、`sharp`、`dotenv` 與 `@huggingface/transformers`。
- 保留最小化的伺服器啟動方式：`npm start`。
- 前端的格數驗證與幀座標計算抽成可測試的純函式模組。

## 測試與驗收

自動測試涵蓋：

- 預設 5×5、25 幀、12 FPS 設定有效。
- 總幀數超過格子容量時拒絕。
- 25 幀的列／欄索引依左到右、上到下計算。
- 背景定位能涵蓋第一格、列尾、下一列與最後一格。
- Express 首頁與靜態資源可正常提供。
- 舊的 `/api/jobs` 不再存在。

手動驗收涵蓋：

- 載入現有 5×5 spritesheet 後能立即預覽。
- 播放、暫停、逐幀、循環及 FPS 調整正確。
- 完整圖表格線與動畫格數一致。
- 瀏覽器 Network 面板沒有圖片上傳請求。
- 不需要 NVIDIA API key、FFmpeg 或模型檔即可啟動。

## 非目標

- 不修改、切割、下載或重新輸出 spritesheet。
- 不提供角色生成、補幀、去背或動作修正。
- 不長期保存最近使用的圖片或播放器設定。
- 不部署公開網站。
